## 1. Sumário Executivo e Perfil de Risco da Skill

A skill **`/test-fix`** atua como o depurador reativo de resposta ultrarrápida do Antigravity SDD 2.0. Seu escopo operacional é diagnosticar quebras determinísticas e pontuais de testes unitários ou de integração levantadas no terminal durante os ciclos de TDD (`/implement`), consolidação de código (`/refactor`) ou auditorias de revisão (`/review`), isolando a causa raiz em exatamente uma frase e aplicando remediações estritamente cirúrgicas no código de produção.

### Arquitetura de Execução e Ferramentas Acionadas
Diferente das demais skills que delegam tarefas pesadas a subagentes isolados em sandbox de contexto, a skill `/test-fix` possui como decisão arquitetural fundamental a **execução 100% no Orquestrador Principal, sem instanciar subagentes** ([`doc/skills/test-fix/README.md#L21-L31`](file:///e:/Codigos/antigravity-agentic-workflows/doc/skills/test-fix/README.md#L21-L31)).
- **Objetivo da Decisão:** Eliminar o custo de *boot* de tokens (3.000 a 8.000 tokens por invocação de subagente) e suprimir a latência de *cold start* para reparos de 1 a 5 linhas de código.
- **Ferramentas Acionadas:** Leitura de arquivos (`view_file`), edição de código (`edit_file`), execução de testes via terminal CLI (`run_command`: `pytest`), consultas opcionais ao Obsidian Vault via `@obsidian` e comandos Git para criação de micro-checkpoints (`git commit -m "checkpoint(test-fix): ..."`) ou reversão cirúrgica de falha (`git checkout -- <modified_src_files>`).

### Superfície de Ataque e Riscos Identificados
- **Perspectiva A (Meta-Agentic Security):** A decisão de rodar 100% no Orquestrador Principal faz com que a ingestão de saídas de testes, logs de erro e *tracebacks* do pytest ocorra na sessão mais privilegiada do sistema. Como salvaguarda mitigadora, os tracebacks são obrigatoriamente delimitados por `<untrusted_traceback>...</untrusted_traceback>`, instruindo o modelo a ignorar instruções imperativas em mensagens de asserção (ASI01/LLM01). Adicionalmente, o risco de agência excessiva (LLM03/ASI02) decorrente do antigo `git reset --hard && git clean -fd` foi eliminado com a substituição mandatória por reversão cirúrgica restrita aos arquivos tocados em `src/`.
- **Perspectiva B (Downstream Code Security):** A antiga exceção que permitia alterações em arquivos de teste foi revogada. O invariante "Unconditional Test Inviolability" agora é garantido mecanicamente via portão de pré-commit determinístico (`git diff --exit-code -- tests/`), impedindo que o agente afrouxe asserções para cumprir a regra do Double-Strike (ASI10).

### 📌 [TESTFIX-LLM10-04] Injeção de Parâmetros e Comandos Shell via Interpolação de Nomes de Testes no Pytest
- **Categorias OWASP:** `LLM10 (Improper Output Handling)` / `ASI05 (Unexpected Code Execution)`
- **Severidade Original:** 🟡 **Média**
- **Status de Mitigação:** 🟢 **Totalmente Mitigado**
- **Localização Exata:** [`SKILL.md#L13,L22,L24`](file:///e:/Codigos/antigravity-agentic-workflows/skills/test-fix/SKILL.md#L13), [`test-fix-protocol.md#L16,L38`](file:///e:/Codigos/antigravity-agentic-workflows/skills/test-fix/references/test-fix-protocol.md#L16), [`diagnostic-report-template.md#L49`](file:///e:/Codigos/antigravity-agentic-workflows/skills/test-fix/resources/diagnostic-report-template.md#L49), [`doc/skills/test-fix/README.md#L35,L82,L101`](file:///e:/Codigos/antigravity-agentic-workflows/doc/skills/test-fix/README.md#L35).
- **Descrição Técnica do Risco (Vetor de Ataque / Falha):**  
  A passagem de seletores `-k <test_name>` sem aspas no shell PowerShell/Bash permitia que caracteres especiais em testes parametrizados (ex.: colchetes, hífens, aspas) causassem injeção de opções no pytest ou comportamento inesperado no shell CLI.
- **Evidências da Mitigação Concretizada:**  
  1. Padronização do apontamento direto e exato do nó do teste (`<test_file>::<test_name>`), eliminando a fragilidade do filtro `-k`.
